# 三個 NUTN 候選問題與 Agent Necessity Test

狀態：第一週討論草稿。以下痛點與使用情境是待驗證假設，不是訪談結果；資料是否公開、格式與可取得性也尚未查證。

後續選題：已由課綱與作業要求理解方向，收斂為「以教師範例為參考的作業規格與完成度檢查助手」。目前定義見 [專案題目與範圍定義](week2-proposal.md)；以下保留第一週候選問題紀錄。

## 1. 課綱閱讀與作業要求整理

- **誰遇到問題？** 同時修多門課、需要整理評分方式與作業時程的學生。
- **目前痛點假設：** 課綱格式各異，重要要求散落在不同 PDF，手動比較容易漏看。
- **需要哪些資料或工具？** 使用者提供的課綱 PDF、PDF 文字擷取、來源頁碼索引、結構化欄位驗證。
- **Why might an Agent help?** 當使用者提出跨課程問題時，系統可能需要先找文件、讀取相關頁、比對矛盾並追問缺漏；多步工具選擇才可能需要 Agent。
- **Could deterministic software solve this better?** 若只需從固定格式課綱擷取截止日，規則式解析或單次模型擷取更簡單。只有需要跨文件追查與澄清時才評估 Agent。
- **最小驗證：** 取得 3 份經允許使用的課綱，人工標記評分比例、作業與日期，比較規則式和模型方法。輸出須附原文頁碼，未提供日期時必須標「未載明」。
- **Week 2 決策依據：** 記錄欄位正確率、無根據內容數量與人工修正時間，再決定是否值得採用 Agent。

## 2. 課表衝堂檢查與選課方案比較

- **誰遇到問題？** 需要同時考量必修、選修、空堂與個人時間限制的學生。
- **目前痛點假設：** 多個候選課程與個人限制難以一起比較。
- **需要哪些資料或工具？** 經確認的課程時間資料、使用者偏好、時間區段解析器與約束求解器；不需要學校帳號或代替使用者選課。
- **Why might an Agent help?** 可透過對話釐清「週五儘量空出來」等偏好，呼叫求解器並解釋哪些條件造成無解。
- **Could deterministic software solve this better?** 是。衝堂、學分加總與條件篩選應交給確定性程式。若使用者能直接填表，可能完全不需要 Agent。
- **最小驗證：** 先用人工製作並標示為測試資料的 10 門課，涵蓋相鄰時段、不連續上課時段、必修衝突及無解案例。
- **Week 2 決策依據：** 衝堂判定與硬性條件須全部正確，再比較對話輸入是否確實比表單省時；不宣稱符合畢業資格。

## 3. 校園活動彙整與個人化推薦

- **誰遇到問題？** 想參加校園活動，但難以追蹤多個公告來源的學生。
- **目前痛點假設：** 活動時間、地點與報名期限散落在不同公告，且可能更新或重複發布。
- **需要哪些資料或工具？** 待確認的公開校園公告、來源網址與擷取時間、活動欄位解析、去重與過期判定、個人興趣及可參加時段。
- **Why might an Agent help?** 對自然語言需求，可查詢多個來源、補讀缺漏資訊，依時間與興趣形成有來源依據的建議。
- **Could deterministic software solve this better?** 固定來源的定期擷取、去重、截止日判斷與時間篩選應使用規則。若資料已有結構化欄位，一般搜尋與篩選介面可能已足夠。
- **最小驗證：** 手動蒐集 10 則經確認可使用的公告，標註發布日、活動日、報名截止、網址及重複活動；資料不足時顯示未知。
- **Week 2 決策依據：** 比較欄位正確率、過期活動誤報與找到合適活動所需時間。活動推薦僅供使用者挑選，不自動報名。
